TourAPI 연동 점검

개발용 임시 화면입니다. 호출 1건이 개발계정 일일 한도(1,000건)를 그대로 소모합니다.

검증 시나리오

  • · ① 목록 조회 areaBasedList2 로 item 이 1건 이상 파싱된다
  • · ② 상세 조회 detailCommon2 — 결과 1건이라 item 이 객체로 와도 파싱된다
  • · ③ 오류 처리 외부 API 실패가 502 Bad Gateway 로 내려온다
  • · ④ 인증키 비노출 응답 본문·오류 메시지에 serviceKey 평문이 없다
  • · ⑤ 카카오 좌표 변환 주소 → 좌표 + 법정동 코드 10자리를 받아온다
  • · ⑥ 법정동 코드 ldongCode2 로 시도 → 시군구 목록이 내려온다
  • · ⑦ 장소 변환 PlaceService 가 TourApiDto 를 PlaceDto 로 변환한다
  • · ⑧ 가중치 추첨 인기 지역이 가중치 비율만큼만 뽑히고, 제외 지역은 안 나온다
  • · ⑨ 서비스 분류코드 categoryCode2 로 대→중→소 분류가 내려온다

④ 중 서버 로그까지 확인하는 항목은 화면에서 볼 수 없습니다. ./gradlew test --tests "*TourApiClientLiveTest" "-Dtourapi.live=true" 로 확인하세요.

① 목록 조회 (areaBasedList2)

    아직 조회하지 않았습니다.

    ② 상세 조회 (detailCommon2)

    아직 조회하지 않았습니다.

    ③ 오류 처리 (502 매핑)

    없는 contentId 로 상세를 조회해 ExternalApiException 을 일부러 발생시킵니다. 응답이 502 Bad Gateway 이고 메시지에 인증키가 없으면 통과입니다.

    ⑤ 카카오 주소 → 좌표 (로컬 API)

    시딩이 시군구 좌표를 얻은 경로입니다. 응답의 bCode 앞 5자리가 시군구 코드이며, 시딩은 이 값이 기대한 코드와 같을 때만 채택했습니다. 동명이의 주의 — "중구" 처럼 여러 시도에 같은 이름이 있으므로 항상 시도명을 붙입니다.

    아직 조회하지 않았습니다.

    ⑥ 법정동 코드 (ldongCode2)

    시도 코드를 비우면 시도 목록, 시도 코드를 넣으면 그 아래 시군구 목록이 내려옵니다. 시딩은 이 목록을 돌며 카카오로 좌표를 채웠습니다.

      아직 조회하지 않았습니다.

      ⑦ 확정 지역 주변 장소 (PlaceService)

      좌표를 보내지 않습니다. 지역 코드만 보내면 서버가 regions.json 의 확정 좌표를 꺼내 locationBasedList2 를 호출하고, 외부 응답을 도메인 DTO(PlaceDto)로 변환해 내려줍니다. 반경 안에 0건이면 서버가 20km 로 한 번 더 넓혀 재시도합니다.

        아직 조회하지 않았습니다.

        ⑧ 가중치 추첨 시뮬레이터

        외부 API 를 호출하지 않는 인메모리 연산이라 일일 한도와 무관합니다. 인기 지역(weight 0.2)이 나머지(weight 1.0)보다 덜 나오는지, 제외 목록에 넣은 지역이 정말 빠지는지를 봅니다.

          아직 추첨하지 않았습니다.

          ⑨ 서비스 분류코드 (categoryCode2)

          ThrowCategory 에 쓸 cat 코드를 확정하는 화면입니다. 전부 비우면 대분류(cat1), 대분류만 넣으면 중분류(cat2), 대분류+중분류를 넣으면 소분류(cat3)가 내려옵니다. 결과의 코드를 누르면 한 단계 더 내려갑니다.

            아직 조회하지 않았습니다.

            "공원" 은 매뉴얼만으로는 어느 분류 아래인지 확정할 수 없습니다. A01 자연 아래 중분류를 먼저 훑어보시고, 안 보이면 A02 인문 쪽도 확인해 주세요. 찾으신 cat1/cat2/cat3 조합을 알려주시면 ThrowCategory enum 으로 고정하겠습니다.
