던지기 흐름 점검

세션 생성 → 던지기 → 갈래/말래 → 확정 을 실제 API 로 이어서 돌려봅니다. TourAPI 를 호출하지 않으므로 일일 한도를 소모하지 않습니다.

검증 시나리오

  • · ① 세션 생성 RANDOM 세션이 IN_PROGRESS 로 만들어진다
  • · ② 던지기 호출할 때마다 지역이 달라진다 (가중치 랜덤)
  • · ③ 말래 → 재추첨 이미 뽑힌 지역은 다음 후보에서 제외된다
  • · ④ 갈래 → 확정 GO 기록을 남긴 지역으로 세션이 CONFIRMED 된다
  • · ⑤ 추첨 우회 차단 던지지 않고 원하는 지역으로 확정하려 하면 거부된다
  • · ⑥ 지역 검색 검색어로 시군구가 조회된다 (비로그인 허용)
  • · ⑦ 주변 장소 조회 확정 지역 좌표로 장소가 조회된다 (로그인 필수)
  • · ⑧ 거리순 정렬 (arrange=S) S 가 유효한 정렬값인지 확인한다 — 오류코드 10 이면 E 로 내려야 한다
  • · ⑨ 카드 3장 카테고리를 고르면 후보 10곳 중 랜덤 3장이 깔린다
  • · ⑩ 리롤 슬롯당 1회 두 번째 리롤은 거부되고, 다시 받아도 되살아나지 않는다

회차 기록

추첨 우회 시도

앞의 세 개는 거부되어야 정상입니다. 마지막 좌표 바꿔치기만 요청은 통과하고 서버 값으로 덮어써져야 정상입니다 — 지역 코드가 맞으면 좌표는 카탈로그에서 다시 채우므로 거부할 이유가 없습니다.

아직 시도하지 않았습니다.

지역 검색

검색 결과를 누르면 그 지역으로 SEARCH 세션을 만듭니다 (즉시 확정). 지역 직접 검색은 보조 경로라 기능을 얇게 유지합니다.

확정 지역 주변 장소

이 버튼만 TourAPI 일일 한도를 소모합니다. 필요할 때만 누르세요. /api/place/list 는 로그인 필수라 비로그인 상태면 401 이 나야 정상입니다.

좌표는 요청에 넣지 않습니다. 지역 코드만 보내면 서버가 regions.json 의 확정 좌표로 조회합니다.

정렬값 확인

카드 후보는 거리순 + 대표이미지 보장(arrange=S)으로 뽑습니다. S 가 위치기반 조회에서 실제로 받아들여지는지 먼저 확인합니다. INVALID_REQUEST_PARAMETER_ERROR(10) 이 나오면 알려주세요 — 임의로 다른 값으로 바꿔 시도하지 않습니다.

아직 확인하지 않았습니다.

카테고리 카드

카테고리를 처음 누를 때만 TourAPI 를 호출합니다. 같은 카테고리를 다시 누르면 30분 동안은 캐시된 후보에서 같은 카드가 나와야 정상입니다 — 카드가 매번 바뀌면 화면만 왔다갔다 해도 리롤 제한이 풀립니다.
