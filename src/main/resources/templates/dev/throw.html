던지기 흐름 점검

세션 생성 → 던지기 → 갈래/말래 → 확정 을 실제 API 로 이어서 돌려봅니다. TourAPI 를 호출하지 않으므로 일일 한도를 소모하지 않습니다.

검증 시나리오

  • · ① 세션 생성 RANDOM 세션이 IN_PROGRESS 로 만들어진다
  • · ② 던지기 호출할 때마다 지역이 달라진다 (가중치 랜덤)
  • · ③ 말래 → 재추첨 이미 뽑힌 지역은 다음 후보에서 제외된다
  • · ④ 갈래 → 확정 GO 기록을 남긴 지역으로 세션이 CONFIRMED 된다
  • · ⑤ 추첨 우회 차단 던지지 않고 원하는 지역으로 확정하려 하면 거부된다
  • · ⑥ 지역 검색 검색어로 시군구가 조회된다 (비로그인 허용)
  • · ⑦ 주변 장소 조회 확정 지역 좌표로 장소가 조회된다 (로그인 필수)

회차 기록

추첨 우회 시도

앞의 세 개는 거부되어야 정상입니다. 마지막 좌표 바꿔치기만 요청은 통과하고 서버 값으로 덮어써져야 정상입니다 — 지역 코드가 맞으면 좌표는 카탈로그에서 다시 채우므로 거부할 이유가 없습니다.

아직 시도하지 않았습니다.

지역 검색

검색 결과를 누르면 그 지역으로 SEARCH 세션을 만듭니다 (즉시 확정). 지역 직접 검색은 보조 경로라 기능을 얇게 유지합니다.

확정 지역 주변 장소
